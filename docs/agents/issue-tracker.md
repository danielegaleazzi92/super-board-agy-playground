# Issue tracker

Tickets for this project live on the GitHub Project board. Every ticket follows the super-board writing standard.

## Ticket format

## Problem
<1–3 sentences: what is wrong or missing, from the user's side. No implementation plan.>

## Context
- **Where:** <page>, `<route>`
  - a. <step>
  - b. <step>
- **Who:** <who sees it>

![<page> · desktop](https://github.com/<owner>/<repo>/raw/<sha>/<path>.png)

## Fix
<the intended change in 1–3 lines>

## Acceptance Criteria
- [ ] <checkable outcome a test can assert>
- [ ] <checkable outcome>

## Risk
🟢 **Low** · <one line>

## Blocked by
- #<N> — <why>          ← or exactly: - None.

Rules: title `<emoji> [<kind>] <scope>: <what>` under 70 chars; 2-5 checkable acceptance criteria; Risk level plus one line; `## Blocked by` with `- #N - why` bullets or `- None.`; bugs add `## Evidence`.
